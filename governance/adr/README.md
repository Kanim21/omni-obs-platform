# Architecture Decision Records

Each ADR captures one significant decision: the context, the choice, why, and what we'd revisit. ADRs are append-only — superseded ones get a new ADR that links back, never edited in place.

## Index

- [0001 — Federation strategy: Sidecar StoreAPI vs. Receive vs. remote-write](0001-federation-strategy.md)
- [0002 — Kustomize structure: base + components + overlays](0002-kustomize-structure.md)
- [0003 — Defer object storage in the demo](0003-defer-object-storage.md)

## Format

Each ADR follows: **Status**, **Date**, **Context**, **Decision**, **Rationale**, **Consequences**, and where applicable, **When to revisit**. Status is one of: Proposed, Accepted, Deprecated, Superseded.
